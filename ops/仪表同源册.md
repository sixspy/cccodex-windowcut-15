# 仪表同源册（业务窗关账）

定版日期：2026-11-20（当天禁止改口）
适用范围：仪表卡、窗口条带、重开台账、审计、争用 五处计数口径

## 一、选定路径：乙路径

**关窗 / 开窗 / 重开 / 入账 / 物化 / 暂存 / 争用登记，与 `dash_counter`
影子表刷新强制同事务；刷新失败则业务行与计数行一起回滚。**
`open_windows` / `closed_windows` 等计数只从 `dash_counter` 读取。

- 甲路径（仪表每次直接聚合 `windows` 实表、禁止缓存）**不采用**，也不得在
  任何读路径回退到实表聚合。
- 乙路径是唯一正确性口径：写事务内由 `db.refresh_dash_counters()` 从实表
  派生并 UPSERT 到影子表；读事务（`/api/dashboard`、`/api/windows` 的
  `counts`）只读影子表。
- **禁止两边混用**：仪表与条带同一个数字只能来自 `dash_counter`。审计视图中
  的「同源校验」仅作诊断比对，不参与任何计数展示。

## 二、五处同态约束

| 面 | 数据来源 | 收敛动作 |
|----|----------|----------|
| 仪表卡 | `dash_counter` | 同事务刷新 |
| 窗口条带 | 行来自 `windows`，计数来自 `dash_counter` | 同事务刷新 |
| 重开台账 | `reopen_ledger`（状态 `已重开`） | 重开与改窗同事务 |
| 审计 | `audit_trail` `window_close` / `window_reopen` | 与业务同事务 |
| 争用 | `contention_log` + `dash_counter.contention` | 争用登记独立提交 |

## 三、重开空桩的收敛

旧版 `reopen-stub` 只写台账、不改 `windows`，造成「已关闭」计数包含
实际已重开的幽灵窗。自本册定版起：

- `POST /api/windows/{id}/reopen-stub` 按 **作废重算** 落地：已关闭且世代
  匹配的窗口置为「开启」、`generation+1`、清空 `seal_token`，台账置
  「已重开」，写 `window_reopen` 审计，并同事务刷新计数。
- 启动时 `db.init_db()` 对历史「空桩登记」台账做一次收敛（同世代补执行，
  否则台账置「已重开」），随后从实表重建 `dash_counter`，消除存量漂移。

## 四、争用

两人同时关窗必须占窗锁 `window:{id}`；后到者只允许：

1. 在 `contention_log` 记一条 `争用`；
2. 刷新 `dash_counter.contention` 并立即提交（不得被 409 回滚吞掉）；
3. 不写窗口业务行、不写 `window_close` 审计、不刷开/关窗计数。

## 五、验收

- 夹具复现「仪表与条带数字不一致」→ 影表缺失/漂移、幽灵窗，先见红。
- 双人同时关窗争用 → 后到者争用被吞，先见红。
- 两条红测齐备后才允许改 `audit_svc` / `windows_svc` / `reopen_svc` 读计路径。
- 全绿标准：`/api/dashboard`、`/api/windows.counts`、`dash_counter`、
  台账、审计、争用五处数字一致；且只改卡片样式/文案不算过关。
